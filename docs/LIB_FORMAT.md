# 书库：数据格式与写作规范

书库是 90 天主线之外的精读库：按书分卷，每个**单元**＝1–3 段原文＋导读＋重点分析＋字词＋思考题＋小测＋卡片＋名句。学习者可以在「📚 书库」里随意读，也可以选一条**专题路线**（一本书从头到尾）按每周学习日排进「今日」。

本文件是撰写书库内容的唯一依据。改规范先改这里。

## 一、文件分工

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `tools/lib_books.json` | 主执行端 | 书目：书号、书名、时代、颜色、目标单元数、简介、路线名 |
| `tools/lib_spec/<书号>.json` | 撰写者 | 选篇与原文定位（每单元 1–3 段） |
| `tools/lib_notes/<书号>/*.json` | 撰写者 | 讲解（可分多个文件，如 `01.json`、`02.json`，每个 20 单元左右） |
| `data/lib/text/<书号>.js` | 生成 | `.venv/bin/python tools/extract_lib.py --book <书号>` 抽出的原文（带来源与 SHA-256） |
| `data/lib/note/<书号>.js`、`data/lib/index.js` | 生成 | `node tools/build_lib.js` 组装 |

**只改自己负责的书号下的 spec 与 notes**；`data/lib/` 永远不手改。

## 二、选篇与原文定位：`tools/lib_spec/<书号>.json`

```json
{
  "book": "shijingf",
  "units": [
    {
      "id": "shijingf_taoyao",
      "t": "桃夭",
      "a": "《诗经·周南》",
      "why": "婚嫁诗的代表，'之子于归'的出处",
      "passages": [ { "kind": "bracket", "file": "诗经.txt", "title": "桃夭" } ]
    }
  ]
}
```

- `id`：`<书号>_<拼音或英文短名>`，只用小写字母、数字、下划线，全书库唯一。
- `t` 标题（简体）、`a` 出处（如「《诗经·周南》」「李白」「《红楼梦》第三回」）、`why` 选篇理由（一句话，说明为什么这篇值得精读）。
- **单元顺序就是阅读顺序**（专题路线按此排）。
- `passages`：1–3 段，每段一个定位，可带 `t` 覆盖本段小标题（如「其一」「第二段」）。定位方式与主线 `tools/text_spec.py` 完全相同（实现见 `tools/extract_texts.py`），先看那里的现成例子：

| kind | 用于 | 必填字段 |
| --- | --- | --- |
| `bracket` | 以【标题】起头的文件：诗经、楚辞、花间集、南唐二主词、纳兰词、元曲、聊斋志异 | `file`、`title`（【】里的完整文字）；重名时加 `meta`（标题行余下部分须含的字）或 `has`（正文须含的字） |
| `chtxt` | 唐诗三百首、宋词三百首（以「○ 标题 / 作者」起头） | `file`、`title`、`author`（繁体，与文件一致） |
| `ss` | 世说新语 | `pian`（如「德行第一」，繁体）、`has`（该则正文里一段独有的字，繁体） |
| `lines` | 按行号取（晋书等） | `file`、`a_line`、`b_line`、`expect`（首行须含的字）、可选 `pick`（只取其中几行） |
| `span` | 从某字串取到某字串（小说、戏曲、传习录、人间词话、小说史略等长文） | `file`、`start`、`end`（都含在结果里）、可选 `after`（起搜行号）、`unwrap: true`（古登堡本硬换行时必须加） |
| `wiki` | 已登记的维基文库页（`sources/wikisource/`） | `file`、`section` 或 `start`/`end` |

- 文件名：`古籍下载` 里的直接写文件名（`诗经.txt`）；第二、三批写相对路径（`古籍下载2/聊斋志异.txt`、`古籍下载3/人间词话_王国维_Gutenberg_v001.txt`）。
- 字串一律照源文件原样（多数是繁体）。
- 长文节选：每段 **150–1500 字**，取最能体现本单元要点的完整段落，在句末结束。
- 看源文件：`.venv/bin/python tools/lib_peek.py <文件> <关键字或行号> [行数]` 打印带行号的原文，用来找 `start`/`end`/行号。
- 检查定位：`.venv/bin/python tools/extract_lib.py --book <书号>`（全部抽取并写出）；只看一个单元加 `--show <单元id>`。
- **不得与主线原文重复**（主线原文见 `data/texts.js`）：书库原文与主线任何一段有连续 40 字相同即报错。

## 三、讲解：`tools/lib_notes/<书号>/*.json`

```json
{
  "shijingf_taoyao": {
    "intro": "导读，60–200 字：这篇是什么、处在什么位置、读它要抓什么。",
    "focus": [
      "重点分析一，40–160 字：写法、结构、意象、史笔或人物，必须落到原文的具体字句。",
      "重点分析二……",
      "重点分析三（可选，2–3 条）"
    ],
    "notes": [["夭夭", "茂盛而美好的样子"], ["灼灼", "花色鲜明"]],
    "think": ["一道需要自己下判断的思考题", "参考思路，30–120 字，给出判断的依据和边界，不给标准答案"],
    "quiz": [
      ["题干", ["正确答案", "干扰项", "干扰项"], "解析：为什么对、错在哪"],
      ["……", ["……", "……", "……"], "……"]
    ],
    "cards": [["卡片正面（问题或原句）", "卡片背面（答案或要义）"], ["……", "……"]],
    "line": ["名句：本单元原文里的连续字串", "原创用法例句：今天在什么场合怎么用这句话"],
    "tags": ["婚嫁", "比兴"]
  }
}
```

**数量下限（校验脚本强制）**：`intro` ≥ 60 字；`focus` 2–3 条、每条 ≥ 40 字；`notes` ≥ 8 条；`think` 2 项、参考思路 ≥ 30 字；`quiz` ≥ 2 道、每道 3 个不同选项且**第一个是正确答案**（程序会打乱顺序）；`cards` ≥ 2 张；`line` 2 项；`tags` 1–4 个。字数只数汉字。

**写作纪律（违反即返工）**

1. **原创**：用自己的话讲。不摘抄、不点名转述任何现代注本和研究著作（程俊英、唐圭璋、萧涤非、余嘉锡、袁行霈、叶嘉莹、王仲闻、张友鹤、陈寅恪、田余庆、谭其骧、顾学颉、李冰若等，校验脚本会拦）。可以引古人（如《毛诗序》、钟嵘、严羽、金圣叹、脂砚斋）**但只能引你确有把握的原话**，拿不准就转述且不加引号。
2. **紧扣原文**：每条 focus 都要指向原文里的具体字句；`notes` 的每个词条必须在本单元原文里**原样出现**（校验）；`line[0]` 必须是本单元原文里的**连续字串**（校验，标点也算），5–40 字。
3. **史实与存疑**：年代、世系、地名、官职拿不准就不写；有争议的写"存疑"并说明分歧（例：北燕始年 407/409）。十六国诸燕部分尤其严格。
4. **不虚构用例**：`line[1]` 是你原创的今日用法例句（如"项目复盘会上……"），不要写"某某曾在某文中用过"。
5. **小测要考理解**：考词义、写法、因果、人物动机、作者立场，不考无意义的数字；干扰项要像样；解析说清为什么。
6. **卡片**：正面一问或一句原文，背面一句话答案；适合三秒复述。
7. **简体中文**，标点全角；古人名、书名、专名照常用字（"慕容儁"不改"俊"）。
8. **语气**：写给有阅历的成年人：直接、具体、不说教、不堆形容词，不用"让我们""总之""值得一提的是"。

## 四、验收命令（交付前必须全部通过）

```bash
.venv/bin/python tools/extract_lib.py --book <书号>      # 原文全部抽取成功（写出 data/lib/text/<书号>.js）
node tools/validate.js --lib <书号>                       # 本书格式、字数、名句与字词在原文中、不与主线和其他书重复、简体
```

`node tools/build_lib.js`（组装全部书）由主执行端统一运行，撰写者不要运行。多人并行时只动自己书号的文件。

交付时报告：单元数、原文段数、原文汉字数、讲解汉字数，以及你没把握、需要主执行端复核的条目。
